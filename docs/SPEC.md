# Blocry Pool, build spec

Unofficial, phone-first PWA showing lane availability at the Blocry swimming pool
(Louvain-la-Neuve). Source: a SharePoint Excel workbook the pool publishes, one sheet per week.
Hosted on GitHub Pages at `https://jdelsoir.github.io/blocry-pool/` (base path `/blocry-pool/`).

## Hard rules (apply to every file: code, comments, UI text, README, commit messages)

- Never use em dashes or en dashes (the characters U+2014 and U+2013, or `--` as a pause). Use commas, parentheses, hyphens in ranges (`08:40-09:00`) or separate sentences.
- No personal names, emails or account identifiers anywhere in the repo. The SharePoint share URL contains a person's name, so it lives ONLY in the GitHub Actions secret `SHEET_URL`. Never hardcode it, never echo it in logs.
- Never commit the `.xlsx` file. `.local/` is gitignored scratch space (contains `pool.xlsx`, `prototype.src.html`, `pool-configuration.png`, and a venv at `.local/venv` with openpyxl, pytest, pillow).
- No Blocry logo and no photos from csblocry.be. The app uses its own lane-mark icon and says it is unofficial, linking to `https://csblocry.be/piscines/`.
- Vanilla HTML/CSS/JS, no framework, no build step, no npm dependencies at runtime. Google Fonts allowed (Exo 2, Teko, Open Sans) with system fallbacks.

## Source workbook facts (verified)

- 76 sheets so far; a new sheet is appended each week. Only the last 1-2 are visible, older ones hidden (still present). Sheet order is chronological. A few junk sheets (`Feuil1`, `Feuil2`, `Feuil4`) are empty.
- Grid: a header row containing `25m` / `50m` pairs (usually row 3). Rows below = half-hours 07:00 to 22:00 (30 rows). Two time columns (from, to) left of the grid: usually B and C in current sheets, A and B in the oldest. Day columns come in pairs (25m, 50m), Monday to Sunday.
- Row above the header (row 2) has either day names (`LUNDI`, `MARDI ` with stray spaces, sometimes `LUNDI 23`) or real datetimes (oldest sheets).
- Title in row 1 (A1 or C1 or D1), e.g. `Horaire du 5 au 11 octobre`, `Horaire du 29 sept au 5 octobre`, `Horaire du 27 au 2 novembre`, `Horaire du 23 février au 1 er mars`, `Nombre de couloirs de nage (du 21/10 au 27/10)`, or no date at all (`1ere semaine Paques`). Sheet names carry similar text (`Semaine du 30 au 6 juin` really means 30 June to 6 July). NO YEAR anywhere.
- Cell values: int lane count; `0` = that length not set up; empty = closed / nothing; strings mixing a number and a note (`4 Attention fond mobile à 70 cm!`, `8(Arrêt de la nage et sortie de l'eau de 8h40 à 9h)`, `15         0` = two numbers in a cell merged across the 25m+50m pair); pure notes (`changement de 8h40 à 9h*`, `Changement de configuration...`, `sortie de l'eau de 18h à 18h20*`).
- Merged cells: changeover banners merged across several days (e.g. D7:M7), closure banners (`FERMÉ SAMEDI ET DIMANCHE` merged N4:Q5 or larger), `Fermeture pour compétition`, `Fermeture exceptionnelle à 17h30`, `Fermeture à 18h`.
- Footnote rows below the grid (row 34+) are prose; ignore.
- Physical pool: 10 lanes of 50m, or a movable pontoon splits each lane into a 25m (A side) and 23.5m (B side) lane, so up to 20 short lanes. Usual public max is 8 x 50m or 16 x 25m but the sheet regularly shows up to 19-20 x 25m and 9-10 x 50m (real, lanes are sometimes divided). Only flag a slot as `suspect` when `ceil(l25 / 2) + l50 > 10` (impossible even with 10 lanes).

## Data contract: `site/data/schedule.json`

```json
{
  "version": 1,
  "generatedAt": "2026-10-03T08:00:00Z",
  "source": { "lastModified": "2026-10-03T07:12:06Z", "sheetCount": 76, "url": "https://csblocry.be/piscines/" },
  "weeks": [
    {
      "start": "2026-09-28",
      "title": "Horaire du 28 sept au 4 octobre",
      "sheet": "Semaine du 28 sept au 4 octobre",
      "days": [
        {
          "date": "2026-09-28",
          "closed": null,
          "slots": [
            { "t": "07:00", "l25": 0, "l50": 8 },
            { "t": "08:30", "l25": 0, "l50": 0, "change": "changement de 8h40 à 9h" },
            { "t": "09:00", "l25": 8, "l50": 0, "note": "Attention fond mobile à 70 cm!" },
            { "t": "12:00", "l25": 19, "l50": 0 },
            { "t": "17:30", "closed": "Fermeture à 18h" },
            { "t": "19:00", "l25": 0, "l50": 3, "suspect": true }
          ]
        },
        { "date": "2026-10-10", "closed": "FERMÉ SAMEDI ET DIMANCHE", "slots": [] }
      ]
    }
  ],
  "warnings": [ { "sheet": "...", "date": "2026-09-28", "t": "12:00", "msg": "..." } ]
}
```

Rules:
- `weeks` sorted by `start` (always a Monday), each with exactly 7 `days` Monday..Sunday.
- Include only weeks with `start >= monday(today) - 7 days` (today = UTC date at run time, overridable with `--today YYYY-MM-DD`), plus all later weeks. Typically 2-3 weeks.
- `slots`: only half-hours that carry information. A half-hour with no value in both columns and no note is omitted (closed). `t` is the slot start `HH:MM`.
- `change` (string, trailing `*` stripped, whitespace collapsed): pool reconfiguration pause during this half-hour. Lane numbers on a change slot are whatever numbers the cell had (often 0).
- `note`: free text that came with a number in the cell.
- slot-level `closed`: a closure note covering this half-hour while other slots of the day are open. Day-level `closed`: the whole day is closed (all of its cells are a closure note or the day has no data at all while being covered by a closure banner). Day with simply no slots and no note: `closed: null, slots: []` (treat as closed in UI).
- `suspect: true` only per the 10-lane rule above; also append a `warnings` entry.
- Parse failures never crash the run on one bad sheet: skip it, add a `warnings` entry. The run fails (exit 1) only if zero weeks could be produced for the window, so CI keeps the last good file.

### Week date inference
1. Parse start day (+ month if present) and end day + month from the title, falling back to the sheet name. French months incl. abbreviations and accents (`sept`, `oct`, `nov`, `déc`, `decembre`, `février`, `fevrier`, `aout`, `août`, `1er`, `1 er`). If the start has no month: same month as end unless start day > end day, then previous month.
2. Row-2 datetimes, when present, win.
3. Year: choose the year making the start date a Monday; if several candidates, the one closest to (and consistent with) the neighbouring sheets in sheet order, anchored on `today` for the last sheet. Never produce a week whose start is not a Monday; warn and skip instead.
4. Title end date that disagrees with start+6 days: trust the start, warn.

## App requirements (from the approved prototype `.local/prototype.src.html`, version 4)

Use the prototype's visual language and logic as the starting point: tokens, fonts (Exo 2 800 italic caps for titles with the double blue rule, Teko for numbers, Open Sans body), blue `#3CABE1` = 50m, magenta `#C73274` = 25m, orange `#F39C12` = "now", grey panels with 3px blue bottom border, light + dark themes via `prefers-color-scheme`. Full-screen app (no phone frame, no proposal text): the phone IS the frame.

- Bottom tab menu: **Agenda** and **Semaine** (EN: Agenda / Week). Top bar: lane-mark icon + screen title, FR | EN switch. Language defaults to French when `navigator.language` starts with `fr`, else English; remembered in localStorage. All UI strings translated; day/month names localized. Source notes stay in French in FR; in EN, closures show "Pool closed" and changeovers show "Pause, pool reconfiguration HH:MM-HH:MM" using times parsed from the note.
- Shared filters across both screens: pool length (25m and 50m / 25m / 50m) and, on Agenda, time of day (All day, Morning <12h, Lunch 12-14h, Afternoon 14-18h, Evening 18h+). NO lane-count filter anywhere. Filters persisted in localStorage.
- **Agenda**:
  - "Now" card: Open/Closed pill (orange dot), big 25m and 50m counts, pool plan, "This setup until HH:MM, pool open until HH:MM".
  - Filter bar on ONE line showing only the current choices as buttons ("Bassin 25m et 50m ▾", "Quand Toute la journée ▾"). Tap opens that filter's options below; choosing one collapses it.
  - "Next session" line for the active filters.
  - Horizontal day strip: every day from today to the last published day, each with a 30-tick sparkline of matching half-hours; today marked.
  - Session list for the selected day. Non-matching sessions are REMOVED (not greyed). Bars for a filtered-out length are hidden. Consecutive half-hours with identical visible lane counts merge into one block. Changeover pauses shown only when adjacent to a visible session. Slots with `note` show it. `suspect` slots show a small warning ("Chiffre douteux dans l'horaire source" / "Suspicious figure in the source schedule"). Empty-day and closed-day states.
  - Footer line: "Horaire mis à jour il y a X" from `generatedAt`, and source link "Source: csblocry.be (non officiel)".
- **Semaine**:
  - Pool length segmented control (Les deux / 25m / 50m) + week navigation across every week in the data, starting on the current week.
  - "Next openings" chips (5): only merge back-to-back blocks whose visible lane counts are equal.
  - Heatmap grid 07:00-22:00 x 7 days, 15px rows; cell shade by lanes (cap 16 for 25m, 8 for 50m, values above cap = full shade); both-mode splits the cell in two; hatched = closed; dashed = changeover; orange now-line on today's column.
  - Tapping a cell opens a bottom sheet: date and block time, both counts, pool plan, note/suspect/changeover text, Close button.
- **Pool plan** (both screens): 10 rows. `l50` full-length blue rows on top; the remaining rows are split by the pontoon; 25m lanes fill the RIGHT side first (where the public usually swims), then the left. Caption "Plan indicatif, 25m publics à droite" / "Illustrative, public 25m on the right".
- "Now" uses the real clock (Europe/Brussels is the user's zone; using the device clock is fine). If today is not in the data: before the first week show the first week; after the last week show a clear "Le prochain horaire n'est pas encore publié" / "Next schedule not published yet" state with the last update time.
- Data loading: `fetch('data/schedule.json', {cache:'no-cache'})` relative URL. On failure use the service-worker cached copy; if offline show a small banner "Hors ligne, données du ..." / "Offline, data from ...".
- PWA: `manifest.webmanifest` (name "Blocry Pool", short_name "Blocry Pool", id/start_url/scope `/blocry-pool/`, display standalone, theme `#3CABE1`, 192/512/maskable icons), `sw.js` (network-first for navigations and `data/schedule.json`, stale-while-revalidate for static assets, offline fallback, cache name rotated per deploy by CI), `offline.html`. Start from the templates in `~/.claude/skills/static-pwa-ghpages/assets/templates/` and that skill's scripts. Relative asset paths only (no leading `/`). `.nojekyll` in `site/`.
- Accessibility: buttons are real `<button>`s, visible focus, aria-pressed/aria-current, `prefers-reduced-motion`, 44px tap targets in nav, `lang` attribute follows the language.

## CI: `.github/workflows/deploy.yml`

- Triggers: push to `main`, `schedule` four times a day (`17 4,14 * * *` also runs the health job, `17 9,19 * * *`), `workflow_dispatch`.
- Job 1 `update`: checkout, setup-python 3.12, `pip install openpyxl`, `scripts/fetch_schedule.sh "$RUNNER_TEMP/pool.xlsx"` with `SHEET_URL: ${{ secrets.SHEET_URL }}`, `python scripts/parse_schedule.py --in ... --out site/data/schedule.json`. If fetch or parse fails, keep the committed file and continue (warning annotation), do not fail the deploy. If the JSON changed ignoring `generatedAt`, commit and push it as `github-actions[bot]` with message `data: schedule update`. Needs `permissions: contents: write`.
- Job 2 `deploy` (needs update): checkout the updated ref, stamp the SW cache version (skill's `stamp_cache_version.py` logic, inline or copied to `scripts/`), upload `site/` with `actions/upload-pages-artifact`, `actions/deploy-pages`. `permissions: pages: write, id-token: write`, `concurrency: group: pages, cancel-in-progress: false`.
- `fetch_schedule.sh`: `curl -sSL --fail -A "Mozilla/5.0" -c jar -b jar "$SHEET_URL"` once (sets the anonymous guest cookie), then the same URL with `download=1` appended (`?` or `&` as appropriate, strip any `e=` param is not needed) to the output path; verify the file starts with `PK` (zip). Never print the URL. Print the HTTP `Last-Modified` header if any to a sidecar file the parser can read (`--last-modified`).
